# Security policy
This foundation is pre-release; no supported production release or hosted evidence service exists.
Do not disclose exploit details, credentials, personal data or confidential records in public issues.
If enabled by the repository owner, use GitHub's private vulnerability reporting on the Security
tab. If unavailable, open a minimal issue requesting a private channel without sensitive details.
No private reporting channel or response-time SLA is represented as configured.

Provide affected version/commit, minimal synthetic reproduction, impact and suggested mitigation
privately. Maintainer triages, confirms, prepares a patch, tests, and coordinates disclosure and
advisory with the reporter. Request acknowledgement before publishing details; publication timing
is agreed per case. Only passive public intelligence is in scope; no unauthorized scans, credential
collection, surveillance or intrusion.

See [security model](docs/SECURITY_MODEL.md) for dependency, parser, source and extension risks.
