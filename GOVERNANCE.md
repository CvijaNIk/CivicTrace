# Governance
Founder/initial maintainer: GitHub user CvijaNIk. This is a solo-maintained foundation, not a
formal organization or claim of institutional endorsement. Maintainer reviews merges, releases,
source rights, methodology and funding decisions. Contributors retain authorship under Apache-2.0;
no blanket transfer or proprietary relicensing permission is requested.

Use issues for proposals, PRs for concrete changes and architectural decision records for durable
choices. Require tests and data/methodology review. Disclose financial/employment/source conflicts
in a minimal public statement; recuse from affected analytical decisions. Sponsorship never buys
editorial control. No direct merge of unreviewed code or private data.

## Corrections and disputes
Open a correction issue with public source references, affected finding/version and a reproducible
explanation, avoiding personal or confidential data. Acknowledge when capacity allows, reproduce,
record alternative explanations, and publish a versioned correction or reasoned rejection. Keep
prior lineage and label disputed interpretations; remove exposed personal data promptly. Escalate
confidential concerns via SECURITY guidance. There is no promised response SLA.

## Community path
After sustained contributions, invite documented module maintainers with least privilege and
public responsibilities. Seek two-person review for data source releases, statistical claims and
security-sensitive code as capacity grows. Record appointments, recusals and decisions. Conduct
reports involving the maintainer require an independent reviewer when one becomes available;
until then the solo-maintainer limitation is explicit.
